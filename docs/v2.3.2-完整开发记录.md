## 二、技术要点

### 1. 速查崩溃根因
- ui.js `/api/capabilities` 路由运行时读 `docs/capabilities.md`，2.3.1 发布时该文件缺失 → 500「capabilities.md 读取失败」
- 修复：按 2.3.1 实际能力补全速查手册（纯用户手册风格，无版本区分：核心模块 20 项 + 分析能力 + 会话关联 + 工具 75 清单）

### 2. 删除知识 tab
- 三处改动：① TAB_DEFS 移除 knowledge 项；② template 知识占位块移除；③ **tabList computed 增加 TAB_DEFS 存在性过滤**（用户历史保存的全局/项目级 tab 配置可能含 knowledge，渲染时自动忽略，无需手动重置配置）

### 3. 卡片统计文字化
- ProjectCard 统计行：4 个 svg（任务/需求/方案/文件）→ 5 个文字标签（任务/需求/方案/备注/文件）
- 数据源：`noteCount` 后端已提供（getProjectStats），前端直接渲染
- 样式：字体大小/颜色不变；`.stat-label` 加 `opacity: 0.7` 区分标签与数值；`white-space: nowrap` 防挤行

### 4. 自动化测试
- **后端**：已有 node:test 体系（scripts/test/*.test.mjs，15 文件 99 用例），根 package.json 补统一入口 `npm test`（`node --test "scripts/test/*.test.mjs"`——Node 24 需 glob 形式，目录带斜杠不识别）
- **前端**：
  - 依赖：vitest@4 + @vue/test-utils@2 + jsdom（devDependencies）
  - vite.config.js 加 `test` 块（jsdom 环境，include src/**/*.test.js）
  - 用例覆盖：api.js token 附加逻辑（mock fetch + element-plus）、planStatus 状态映射、computeDisplayStatus 延期判断、formatDescription/richTextToPlain 文本处理、ProjectCard 统计文字渲染
  - 运行：`npm test`（frontend 目录，vitest run）

## 五、踩坑记录

1. `node --test scripts/test/` 在 Node 24 报 MODULE_NOT_FOUND：目录参数需用 glob（`"scripts/test/*.test.mjs"`）或显式文件列表，尾斜杠目录不被识别为测试入口
2. vitest 测试 api.js：模块级代码（pluginId/urlToken）在 import 时读 window.location，须在动态 import 前设置 URL；element-plus 需 vi.mock 隔离
3. vite.config.js 源文件含 GBK 乱码注释（历史遗留），edit 匹配需避开乱码区，改文件结尾追加配置
