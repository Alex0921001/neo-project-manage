## 一、版本定位

| 维度 | V1.x（现状） | V2.0（目标） |
|---|---|---|

## 八、踩坑记录

1. **createTask 不接收 done 参数**：完成状态必须走 updateTask 设置，测试脚本直接传 done 被忽略（PM 复测时踩过）
2. **老数据 kind=NULL 筛选漏掉**：SQL 用 `kind = 'note'` 匹配不到 NULL，必须 `COALESCE(kind,'note') = ?` 与读取兜底语义统一
3. **notes.created_at 是纯日期**（非 ISO）：timeline 合并排序需 timeToMillis 归一化两种格式
4. **Windows 临时目录 EPERM**：better-sqlite3 WAL 句柄未释放，测试脚本删除临时目录报错（测试逻辑不受影响，收尾容错即可）
5. **Hono 由平台注入**：不在依赖中，路由无法真起 HTTP 测试，用「fake app 捕获注册 + 直调 handler」验证
6. **manifest tools 是显式声明列表**：新工具必须注册才被平台加载（S5 发现，非自动扫描）
7. **dev 槽位 lib 不完整**：install 时 better_sqlite3 mmap 锁中断导致 db.js 缺失，computeStatus 改动不生效；重装 + 校验完整性解决
8. **中文文件名 URL 编码**：/icons/撒花.png 编码后路由 param 不匹配 → 改英文名 confetti.png
9. **图标 404 根因**：img src 必须带插件前缀 /api/plugins/{id}/ + resolveAssetUrl 处理凭据
10. **absolute 定位输入框重叠**：toolbar 叠在 textarea 上文字会重叠，改 flex 容器（textarea + toolbar 正常流）根治
11. **vuedraggable 搜索过滤不生效**：:list 绑全量数组，搜索态应绑过滤结果
12. **dev 槽位工具连正式库**：实测 dev 槽位注入的是正式 dataDir（plugin-data/neo-project-manage），非文档记载的 dev 隔离目录（plugin-data/dev/neo-project-manage）；dev 测试库数据工具查不到，页面/工具与测试库数据源不一致
13. **Copy-Item 同步 dist 结构损坏**：`Copy-Item src\* dest -Recurse` 遇目标同名目录嵌套/平铺错乱，dist/assets 丢失；应 robocopy /MIR 或先删后复制（已记入部署文档）
14. **archived=0 被转 null 撞 NOT NULL**：UPDATE 参数 `v || null` 把 0 转 null，对 archived 特判保留 0/1
15. **sets 键名与 UPDATE map 驼峰不一致**：`sets.archived_at`（下划线）找不到 map 键 → SQL 拼出 `undefined` 列名，统一驼峰 archivedAt
16. **SCHEMA_SQL 新索引引用迁移列**：旧库无 archived 列时 `CREATE INDEX idx_projects_archived` 直接报错，索引必须放在迁移函数里（加列后再建）
17. **工具「看起来成功但库里没变」的坑**：plugin_dev_reset / disable+enable 不重载后端 lib 模块（插件运行时对后端代码有快照），磁盘代码正确 ≠ 进程内生效，必须重启宿主进程才能加载新 data.js
18. **dev 槽位与正式槽位 dataDir 不同**：dev 运行时读 `plugin-data/dev/{pluginId}`，正式读 `plugin-data/{pluginId}`；排查数据不一致先确认实例，别默认查正式库
19. **EPERM reset 半失败清空 dev lib**：reset 被 better_sqlite3 锁拒绝后，dev 槽位可能残留「只剩 vendor」状态，需改名绕锁重装 + 校验完整性
