### 便利贴互斥规则（V2.1 追加，MCP 工具校验）

#### 规则定义（用户拍板）

1. **已完成任务不允许挂载便利贴**：`createAnnotation` / `createAnnotations` 在任务 done=1 时拒绝
2. **任务完成前置**：`updateTask` done 0→1 时，该任务下所有便利贴必须已确认（confirmed=1），否则拒绝完成
3. **已完成任务便利贴冻结**：`updateAnnotation` 拒绝一切修改（内容 / 类型 / confirmed 状态），报「任务已完成，便利贴已冻结，不能修改」
4. **删除不受限**：`deleteAnnotation` 不拦截（冻结的是修改，删除放行）
5. **取消完成放行**：done 1→0 后重新挂载/修改允许（重新完成时仍要求全部确认）

#### 实现（64600d2 → e6c5e6f）

- 校验写在**数据层**（lib/data.js），MCP 工具与 REST API（前端页面）同时生效
- 前端入口同步隐藏：确认/取消确认按钮 `v-if="!targetDone"`、内容点击编辑加 `!targetDone` 守卫、toggleConfirm 函数级守卫（49c5913）
- 验证：dev 实例实测 create/update/delete 三条链路符合预期

## 七、踩坑记录

1. **双实例分叉（重点坑，再次确认）**：MCP 工具走 community 实例（正式库 `plugin-data/neo-project-manage`），页面走 dev 实例（dev 库）。dev 库的关键数据（1addfdd0 / b4001fe6）用工具查不到属正常，排查需直接查 dev 库或 plugin_dev_invoke_tool
2. **重启丢 dev 注册**：Hana 重启后 dev 槽位注册丢失（devSlots 空），需重新 plugin_dev_install 挂载
3. **updateTask diff 键名 snake_case**：审计变更字段直接取 DB 列名（is_milestone / start_date），前端翻译映射需同时覆盖 camelCase 与 snake_case 两套命名
4. **测试用例与新规则冲突**：既有用例「先完成任务再挂批注」与新规则矛盾，需调整顺序（批注挂载与确认在任务完成前）
5. **审计用例删减**：updateAnnotation 的 kind+confirmed 变更审计验证挪到任务完成前执行（冻结后无法再改）
6. **Windows ESM import 盘符路径**：临时脚本 import 绝对路径需 `pathToFileURL` 转换（ERR_UNSUPPORTED_ESM_URL_SCHEME）
7. **临时目录 EPERM**：测试脚本清理临时 sqlite 目录偶发 EPERM（句柄未释放），不影响测试结果
8. **node --test 目录方式失败**：`node --test scripts/test/` 目录方式报错，需显式指定测试文件
9. **星星居中 margin-top 元凶**：svg margin-top 1px 导致垂直偏移，最终方案绝对定位 + translateY(-50%) 彻底解耦
