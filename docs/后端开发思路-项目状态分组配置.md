### 3. 分组配置读写（P2）

#### 3.1 常量与默认值（`lib/domain/settings.js` 模块级导出）

```js
export const STATUS_GROUPS_KEY = "projectStatusGroups";
// 7 组定义：已延期并入「待开始」，不单独成组
export const PROJECT_STATUS_GROUPS = [
  { label: "预开始", statuses: ["预开始"] },
  { label: "待开始", statuses: ["待开始", "已延期"] },
  { label: "进行中", statuses: ["进行中"] },
  { label: "预结束", statuses: ["预结束"] },
  { label: "已完成", statuses: ["已完成"] },
  { label: "已取消", statuses: ["已取消"] },
  { label: "已归档", statuses: [] }, // 归档是独立维度，不受状态筛选影响
];
export const STATUS_LIMITS = [5, 10, 15, 20, "all"];
```

默认配置（`defaultStatusGroups()` 返回，每次返回新对象，防外部改引用；与需求 4.3 逐字一致）：

```json
{
  "order": ["预开始", "待开始", "进行中", "预结束", "已完成", "已取消", "已归档"],
  "visible": { "预开始": true, "待开始": true, "进行中": true, "预结束": true,
               "已完成": true, "已取消": true, "已归档": false },
  "limit": { "预开始": "all", "待开始": "all", "进行中": "all", "预结束": "all",
             "已完成": "all", "已取消": "all", "已归档": "all" }
}
```

> 配置只描述分组，不描述状态：`已延期` 无键，前端把它并入「待开始」组渲染与计数。

#### 3.2 归一化规则（`normalizeStatusGroups(raw, prev)`）

| 输入情况 | 归一结果 |
| --- | --- |
| 整份配置缺失 / 非 JSON 对象 / `JSON.parse` 失败 | 全量默认值 |
| `order` 缺某组 | 未出现的组按默认顺序追加（已归档恒在最后） |
| `order` 含未知字符串 | 丢弃 |
| `order` 重复项 | 只保留首次 |
| `order` 出现 7 键之外的键（含旧配置残留） | 丢弃该键（旧配置平滑降级，不报错） |
| `visible` 缺某组 | 已归档 `false`，其余 `true` |
| `visible` 值非布尔 | 同上默认值 |
| `limit` 缺某组 | `"all"` |
| `limit` 非 `5/10/15/20/"all"` | 读取：`"all"`；写入：`prev[组]` 的有效值，无 `prev` 则 `"all"`（对应需求「回退到该分组原有效值」） |
| `visible` / `limit` 出现 7 键之外的键 | 丢弃，不写入存储 |
| 多余字段/多余键 | 丢弃，只输出 `order/visible/limit` 三字段，每字段仅 7 键 |

#### 3.3 函数

| 函数 | 位置 | 行为 |
| --- | --- | --- |
| `getStatusGroups()` | `createSettingsModule` 内 | `getSetting(STATUS_GROUPS_KEY)` → `JSON.parse` try/catch → `normalizeStatusGroups(raw, null)` |
| `updateStatusGroups(cfg)` | 同上 | `normalizeStatusGroups(cfg, getStatusGroups())` → `setSetting(STATUS_GROUPS_KEY, JSON.stringify(next))` → 返回 `next`（**不做局部合并，整份覆盖**） |
| `defaultStatusGroups()` | 模块级 | 返回默认配置深拷贝（测试与前端兜底共用） |

#### 3.4 对外暴露（`lib/data.js`）

| 位置 | 改动 |
| --- | --- |
| `lib/data.js:395`（`Object.assign(ctx, …)` 后的解构） | 解构语句追加 `getStatusGroups, updateStatusGroups` |
| `lib/data.js:576-579`（`return { … }` 设置段） | 追加 `getStatusGroups, updateStatusGroups` |

#### 3.5 路由（新增 `routes/modules/settings.js`）

```js
export function registerSettingsRoutes(app, data) {
  app.get("/api/settings/status-groups", (c) => {
    try { return c.json({ ok: true, data: { config: data.getStatusGroups() } }); }
    catch (e) { return c.json({ ok: false, error: e.message }, 400); }
  });
  app.put("/api/settings/status-groups", async (c) => {
    try {
      const body = (await c.req.json()) || {};
      return c.json({ ok: true, data: { config: data.updateStatusGroups(body) } });
    } catch (e) { return c.json({ ok: false, error: e.message }, 400); }
  });
}
```

`routes/ui.js`：`import { registerSettingsRoutes } from "./modules/settings.js";` 并在 `registerMessagesRoutes(app, data)` 之后追加 `registerSettingsRoutes(app, data);`（注册段见 `routes/ui.js:174-193`）。路由为纯设置读写，不涉及 `/page` 与静态资源。

## P2：后端分组配置读写

**目标**：`projectStatusGroups` 可整份读写，旧配置/脏值一律回落默认值。

### 步骤

1. `lib/domain/settings.js` 模块级加 `STATUS_GROUPS_KEY`、`PROJECT_STATUS_GROUPS`、`STATUS_LIMITS`、`defaultStatusGroups()`。
2. 工厂内加 `normalizeStatusGroups(raw, prev)`，按 §3.2 表格实现（顺序、去重、7 键兜底、limit 校验、旧配置键降级）。
3. 加 `getStatusGroups()` / `updateStatusGroups(cfg)`（§3.3），写入走现有 `setSetting`（`settings.js:24`，`INSERT OR REPLACE` 天然整份覆盖）。
4. `lib/data.js` 解构与 `return` 各补两函数（`:395`、`:576-579`）。
5. 新建 `routes/modules/settings.js`，`routes/ui.js` 注册。
6. 新增 `scripts/test/status-groups-config.test.mjs`，断言：
   - 无配置时 `getStatusGroups()` 等于默认值（含 `已归档: false`）；
   - 写入后 `getSetting("projectStatusGroups")` 为 JSON 字符串，`getStatusGroups()` 往返一致；
   - 脏值：`limit` 传 `7` → 写入回落原有效值（首次为 `"all"`）；`visible` 传 `"yes"` → 回落默认；
   - `order` 缺 `已归档` → 自动补到末尾；
   - 旧版配置（曾含 `已延期` 键）写入后读取 → 输出仅 7 键，该键不出现、不报错；
   - 前端漏传某键 → 该键回落默认（`visible` 按组默认、`limit` 为 `"all"`）；
   - 手改库写坏 JSON（`data.setSetting("projectStatusGroups", "{bad")`）→ `getStatusGroups()` 仍返回默认值。

**风险点**：
- `updateStatusGroups` 的 `prev` 必须取「当前已归一化后的有效值」，否则连续两次非法写入会退到默认而不是原值。
- 不要复用 `getMessageConfig` 那套 `parseBool` 语义（它把非 `1/true` 一律当 `false`），本配置需要「非法 → 默认 true」。
