## 3. 数据模型变更

### 3.1 Schema v1 → v3

| 变更 | 说明 |
|---|---|
| v1→v2 | tasks 加 `assignee` / `start_date` / `end_date`（单值，后被 v3 取代） |
| v2→v3 | DROP `assignee` + ADD `assignees TEXT`（JSON 数组）；**DROP INDEX 必须先于 DROP COLUMN**（SQLite 对被索引列 DROP COLUMN 报错，P1-1 修复） |
| 索引 | idx_tasks_start_date / idx_tasks_end_date（迁移内创建，幂等） |
| 脏数据兜底 | parseAssignees / parseMembers JSON 解析兜底 `[]`；listTasks 成员筛选 `json_each(CASE WHEN json_valid(...) THEN ... ELSE '[]' END)` |

### 3.2 字段契约

- 旧字段 snake（project_id / index_num / created_at）+ 新字段 camel（assignees / startDate / endDate）双轨 = 有意设计
- taskRowToObject（工具路径）与 buildTaskTree（REST 路径）输出统一 camelCase
