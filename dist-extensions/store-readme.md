# 项目管理（neo-project-manage）

一个给「人 + Agent」共用的项目管理应用。页面侧用来安排项目、任务与方案；Agent 侧通过 125 个工具直接读写同一份数据，不需要你在中间复制粘贴。包内还带一个 MCP server，Hana 之外的工具也能接入同一份数据。

## 它解决什么问题

多数项目管理工具只能给人看，或者只能给 AI 读。这个应用让两边落在同一份本地数据库上：你在页面上拖任务，Agent 读到的就是改完之后的状态；Agent 建的需求和方案，你在列表里能直接接着改。

## 核心模块

| 模块 | 说明 |
| --- | --- |
| 项目集 / 项目 | 分组归拢、收藏置顶、归档与取消、成员与计划起止 |
| 任务 | 任意层级子任务、优先级 P0~P5、里程碑、负责人、起止日期、日历视图 |
| 便利贴（批注） | 备注 / 决策 / 风险 / 节点四类，可确认；任务完成前必须全部确认 |
| 需求 | 三态流转（待处理 / 已完成 / 已取消），优先级排序、搜索、分页，可关联方案 |
| 方案 | 富文本内容、状态流转、评论、一键转任务、从 txt/md/docx 导入成稿 |
| 评论与版本 | 需求与方案共用的评论表，支持划词引用；内容变更自动存版本快照（保留 50 版），可双栏对照与还原 |
| 验证 | 验证卡 + 验证项清单，支持人工项与 Agent 执行项，进度按项完成度计算，Agent 可回填执行证据 |
| 临时任务 | 随手记，一键转正式任务，已完成项可归档 |
| 消息中心 | 到期提醒与风险提醒聚合推送，提前天数与开关可配置 |
| 全文检索 | 中文本地检索，覆盖项目 / 任务 / 批注 / 方案 / 需求 / 备注 / 文件 |
| 总结与周报 | 项目自动总结、6 条风险规则识别、一键生成周报或阶段总结（Markdown） |
| 审计 | 所有写操作留痕，可按行为与时间范围筛选 |

## 页面侧

- 项目概览：KPI 统计、风险清单、下一步建议、历史总结时间线
- 详情弹窗内可直接前后翻阅，列表行点击预览
- Tab 顺序、显隐、搜索词、排序方式与状态筛选都会记忆
- Ctrl+F 全局检索，命中词高亮，点结果跳回原文
- 任务日历可拖动、可缩放

## 页面形态

应用提供两张卡：

- **整页卡**：站点导航里的「项目管理」入口，全屏打开。
- **同伴卡**：可在页面间移动的普通卡，能拖到主页停靠，适合边聊边看项目进度。

注意宿主限制：整页卡受保护，不能拆窗、不能移出所属页面（会返回 `APP_PAGE_PRIMARY_MOVE_FORBIDDEN`）。要拖到主页停靠，用同伴卡。

## Agent 侧

所有工具以 `neo-project-manage_` 为前缀，输入输出都是 JSON。典型链路：

```
1. list_projects                        → 找到项目
2. get_project { id }                   → 任务树 / 批注 / 文件 / 归档状态
3. get_project_risks { projectId }      → 只读风险 JSON
4. ask_project { projectId, scope }     → 按 scope 取总结 / 风险 / 决策 / 时间线等
5. create_task / create_annotation      → 落地任务与便利贴
6. report_verification_result           → 执行验证项后回填证据
```

批量操作有统一范式：批量新增是事务包裹，任一条失败整体回滚；批量编辑、删除、状态流转是逐条独立校验，返回成功与失败清单。单次上限 50 条。

## MCP 通道

包内自带 `mcp-server/index.js`，供 Hana 之外的工具接入同一份数据库。

| 项 | 说明 |
| --- | --- |
| 工具数量 | 125 个，与 Agent 侧一致 |
| 传输 | stdio（line 与 LSP Content-Length 自动识别）；设 `MCP_PORT` 后转 HTTP |
| 数据目录 | `MCP_DATA_DIR`，默认 `<用户目录>/.hanako/app-data/neo-project-manage-v2` |
| 运行要求 | Node.js 22 及以上（依赖内置 `node:sqlite`） |

接入示例：

```json
{
  "mcpServers": {
    "neo-project-manage": {
      "command": "node",
      "args": ["<HANA_HOME>/apps/neo-project-manage-v2/mcp-server/index.js"]
    }
  }
}
```

**权限提示**：这条通道授予外部进程完整读写权限，误调用会直接改到真实项目数据，且 Hana 内的审计看不出调用方是外部进程。只需要读取时，请在客户端侧限制可用工具。

## 数据与隐私

- 数据保存在本机 SQLite（`数据目录/projects.sqlite`），WAL 模式，外键级联
- 不上传任何服务器，没有账号体系，不发遥测
- 卸载应用不会删除数据文件
- schema 变更在启动时自动幂等迁移，旧数据可直接沿用
- 多进程并发（Hana 与 MCP server 同时打开）靠 WAL + busy_timeout 保证

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `app/resources.read` | 读取工作区路径之外的文件正文（项目文件资产的「读取内容」）。宿主资源通道是唯一合法读盘外的入口 |
| `app/tools.expose-to-model` | 把 125 个工具暴露给模型调用 |
| `app/process.spawn` | 桌面能力：系统文件选择对话框、打开文件、在资源管理器中定位、导入 docx 时调用系统 `tar` 解压 |
| `app/ui.open-external` | 从页面打开外部链接 |
| `app/ui.clipboard-write` | 复制任务 / 方案内容到剪贴板 |

## 兼容与边界

- 最低 Hana 版本：`1.1.0-beta`
- 文件选取、打开文件、资源管理器定位依赖 Windows 桌面环境
- docx 导入依赖系统 `tar`（Windows 10 1803+ 内置），不可用时该项导入会失败，其余功能不受影响
- MCP server 需 Node.js 22+
- 卸载不删数据；需要清空请手动删除数据目录下的 `projects.sqlite`
